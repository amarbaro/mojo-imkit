# mojo-imkit v0.2.0

**Released:** 2026-10-09 · **Commit:** `v0.2.0` · **Previous:** [v0.1.0](v0.1.0.md)

## What it does

An immediate-mode GUI for Mojo apps, drawn by one GPU compose kernel over the app frame.
System SDL3 presents the window and FreeType builds the glyph atlas at startup.

## Highlights

- Construct `Layer(ui.font)` once and call `layer.render(ui)` after `ui.finish()`.
- The reusable `layer.pixels` buffer is ready for `Window.present` when render returns.

## Changes

### Added

- `imkit.layer.Layer`: owns the device context, five device buffers, pinned host output, compiled compose kernel,
  atlas upload, frame uploads, launch, copy back and synchronization.
- Exact pixel comparison against the existing direct compose path, populated/empty/populated reuse checks,
  stable host buffer address check and oversized atlas rejection in `ui_test`.

Timing for 150 commands at 1280 x 720 on RX 7900 XTX: baseline compose 17.79 us, Layer compose 14.58 us,
full Layer render 219.24 us including transfers. These are observed timings, not a claimed speedup;
GPU clock state and host launch overhead affect the comparison.

## Known limits

- Use the same font for the Layer and Ui; atlas replacement after construction is unsupported.
- Dimensions are fixed by `UI_W` / `UI_H`, positive multiples of 16; oversized atlases fail at startup.
- Latin text only; docking, plots with axes, slider, text input, menus and DPI scaling remain future work.
- Checked on RX 7900 XTX and KDE Wayland.

## Upgrade / run

```mojo
from imkit.layer import Layer
var layer = Layer(ui.font)  # once, before the frame loop
# Each frame, after widgets:
ui.finish()
layer.render(ui)
win.present(frame_ptr, Int(layer.pixels.unsafe_ptr()))
```

Run `tools/gate.sh` to check the package. No new dependencies.
