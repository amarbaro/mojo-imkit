## What it does

<!-- Stable description of the program. Carried forward from the previous note; edit only when the product itself changes.
     3 to 6 lines: what it is, who uses it, where it runs (URL/port/binary), how to start it. -->
An immediate-mode GUI for Mojo apps, drawn by the GPU. It takes the idea behind Dear ImGui and imgui-bundle (widgets
are function calls made every frame, no retained widget tree) and builds it in Mojo around a GPU app's own frame:
widgets append to one flat draw list, one `compose` kernel turns that list into an RGBA layer, and the window blends
the layer over the app's picture. No Python UI process, no C++ library, no bundled windowing: the system's SDL3 and
FreeType are called through Mojo's FFI.

First user: [the host app](../the host app)'s engine GUI (run controls, per-fly cards, telemetry over the live scene).

## Highlights

<!-- 1 to 5 bullets a user would notice. Lead with the benefit, not the implementation. -->
- A GUI for Mojo GPU apps with no Python process and no C++ library: buttons, toggles, icon buttons, panels, bars,
  sparklines and text, drawn over your own frame in about 18 to 22 us per frame at 1280 x 720.
- Two system libraries only (SDL3, FreeType), reached through Mojo's FFI; nothing bundled.
- Scripted checks can drive the window with synthetic events while a real mouse is ignored.

## Changes

### Added
- `imkit.window`: SDL3 window, vsync, letterboxed frame + UI layer, `poll() -> Input`, `present`, `push` synthetic
  events, `Input.merge` (no click lost between UI frames), `readable(fd, ms)`.
- `imkit.font`: FreeType glyph atlas (ASCII 32-126, several pixel sizes, 60,928 B for 13/16/22 px).
- `imkit.ui`: `Ui` widgets (panel, button, icon, bar, spark, text, rect, line, tri), the tiled `compose` kernel, a
  dark theme.
- `tools/gate.sh`: precompile plus the three tests.

## Known limits

<!-- Honest list: slow paths, unsupported cases, flaky upstreams, anything UNVERIFIED. -->
- No docking, plots with axes, slider, text input, menus or DPI scaling yet.
- The app owns the device buffers and the compose launch (see README); a helper for that is planned.
- Latin text only (no shaping); UI size fixed at build time (`-DUI_W`, `-DUI_H`, default 1280 x 720).
- Checked on one GPU (RX 7900 XTX, gfx1100) and one desktop (KDE Wayland).
