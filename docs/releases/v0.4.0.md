## What it does

<!-- Stable description of the program. Carried forward from the previous note; edit only when the product itself changes.
     3 to 6 lines: what it is, who uses it, where it runs (URL/port/binary), how to start it. -->
An immediate-mode GUI for Mojo apps, drawn by one GPU compose kernel over the app frame.
System SDL3 presents the window and FreeType builds the glyph atlas at startup.

## Highlights

<!-- 1 to 5 bullets a user would notice. Lead with the benefit, not the implementation. -->
- `Layer` works inside an engine: it takes your DeviceContext, so the UI shares the engine's stream.
- About 15 % faster render (206-208 us vs 238-249 us per frame): a frame uploads only what it drew (23 KB, was 602 KB).
- Harder to misuse: rendering an unfinished frame raises, the font atlas comes from the Ui, a full draw list drops whole
  commands (counted) instead of half a tile.

## Changes

### Changed
- `Layer(ctx, ui)` replaces `Layer(font)`; no type parameter.
- Tile bins are one compact list with per-tile offsets: `compose(img, cmd, bins, off, atlas, src)`; `NBIN`
  (`-DUI_BINS`, default 32,768 entries) replaces `TCAP`.
### Fixed
- A tile with more than 64 commands silently lost the rest; now the whole frame budget is shared and overflow drops
  whole commands, counted in `Ui.dropped`.
